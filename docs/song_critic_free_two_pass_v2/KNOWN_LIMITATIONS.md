# KNOWN_LIMITATIONS (Free-Thinking Two-Pass V2)

1. **Two songs, two backends, one run each, no retry:** 4 cells. An indication, not a statistic; Grok's speed varied between today's tests. Both songs were already known to the auditor (neutral titles do not hide that).
2. **Quality judgment is one reader's,** from the raw answers. The only scripted checks are line ids, quoted Thai fragments and cost. The fragment check cannot tell a quoted lyric from a quoted term of the model's own or a proposed new line, so its "not found" counts overstate inaccuracy; the reading in QUALITY_COMPARISON is the better evidence and is not exhaustive of every sentence either.
3. **The evaluation script was written after the run** (pre-registered as counting only) and changed once after the first look at its output: a range such as `L2-L6` is accepted when both ends exist (production's own structure writes the blank separator line as the end of a section). Prompts, models and raw answers were not changed.
4. **No eight-aspect Songcraft tiles were built.** The brief allows free prose and forbids Python from judging meaning; mapping prose onto eight aspects needs a reading of meaning, so the prototype stores Pass 1 and the final critique whole (`FINAL_CRITIQUES/`); all eight tiles would read "Not Reviewed". The production parser and UI were not touched. Whether a free critique can be mapped to tiles reliably was not tested.
5. **The genre/mood line is in the song data for both arms** (the style comes with the lyrics, as in production). It may serve as an excuse for stillness; it was neither removed (that would change the comparison) nor isolated.
6. **One prototype only.** A Pass 2 wording that asks for the strongest counter-argument to each favourable conclusion, or a system prompt that states that intention is not success, was not tried by design (no tuning after the results). This test says that THIS free-thinking design did not protect the S1 judgment, not that no design can.
7. **Gemma's voice varies** (ดิฉัน/ผม, ครับ/ค่ะ in the same kind of answer) and it sometimes ends with a leaked `<end_turn>`; irrelevant for free prose.
8. **Session:** Gemma = real server-side session (one id per song); Grok = stateless API with the earlier messages replayed. The Grok request wrapper copies the body of `llm_chat.ask_grok` (same URL, model, temperature 0.4, `reasoning_effort: low`, `max_tokens` 4096) to read usage and the finish reason; arm A on Grok used the same wrapper.
9. **Production and AppData untouched:** no change to the production prompt, parser, UI, settings or models; no commit; no audio; no other specialist. The helper's per-call log line was switched off inside the process, so, unlike the previous prototype, nothing was appended to AppData. The raw output was written to a temporary directory during the run and copied here afterwards. ComfyUI keeps its own session history files, as in every Gemma call.
10. An earlier brief ("Two-Pass V1", with a verification prompt and a tagged format) was prepared in a different folder and replaced by this V2 brief before any request was sent; nothing from it was run or used.
