# KNOWN_LIMITATIONS (Song Critic Academy V1)

1. **Content quality was written and checked by the AI Coder, not reviewed by a songwriting teacher or a native Thai lyricist.** The eight lessons (16 files) are original text in Thai and English with original Thai examples; a human review of the wording, the examples and the pedagogy is recommended before release. The Thai is natural to this author's reading only.
2. **References were checked at page / listing level only.** Course pages were fetched; for the books only publisher listings, an excerpt summary and a Berklee Online blog post were found. No book was read in full, so the lessons attach `[Rn]` tags only to claims those pages make (that a course exists, which lesson titles it has, that object writing means writing about an object through the senses). "Source checked" in the UI means exactly that (each reference line says what it supports and its limit). The opening patterns, the six development approaches, the repetition functions and the six endings are our own groupings (labelled `general`).
3. **Pat Pattison's and Stolpe's actual teaching on verse development, repetition or endings is not reproduced and was not verified** (the Berklee course page lists lesson titles only). The lessons do not claim it.
4. **The Songcraft report is still not what a normal Analyze produces** (the production prompt is unchanged by design). The lessons therefore also appear as a list under older-format reports and when there is no report. The in-tile lesson block shows only for a Songcraft report (seeded real candidate answers in the screenshots).
5. **Real Flet evidence:** web mode with a temporary profile in the browser pane (not the packaged desktop executable, not the user's real AppData). Captured at 320, 360 and 560 px. Not captured: Flet desktop; every one of the eight lessons expanded at every width (the Opening, Hook and Development lessons were opened in the real window; the others use the same code path); the English UI at 360/560 (captured at 320).
6. **Real Songwriter test: one topic, one backend** (Gemma local, Test Song 02, no report). Not tested with a real model: a lesson of a song with a Songcraft report (finding block), an Outdated report, Grok, a real refusal at a tight context (these are covered with a fake model on the control tree). The profile used a 32,768-token context, not the user's 19,000.
7. **Preview / Apply / Undo** were not exercised in the real app in this round (no edit was proposed). The existing edit flow is unchanged and its suites pass.
8. **Lesson length:** each lesson is a long scroll when fully open at 320 px (all sections, techniques collapsed). Everything is collapsed by default; a "table of contents" inside a lesson was not built.
9. **Language:** the Thai lessons are the default and the most developed; the English lessons are translations of the same structure and examples, shorter in places. When the UI language is switched, an open page redraws in the new language (the Thai lyrics and examples stay Thai).
10. **User-edited files are not merged on upgrade:** if the user edited a lesson and a newer default ships, the user's file stays and the new default is not shown (delete the file to get it). No "update available" notice exists.
11. **Packaging:** `collect_data_files("music_studio")` should ship the `.md` files, but the frozen build was not run in this task.
12. **Unrelated uncommitted work remains in the tree** (Export Audio and others) and the Song Critic V3 work is also uncommitted. The task-only patch is made against "HEAD + the V3 task patch" (PATCH/clean_base_check.txt) and leaves out the unrelated hunks.
13. **Pre-existing failures** in the wider suite are unchanged (TEST_RESULTS.md); no old test was edited except `tests/test_songcraft.py` (V3, uncommitted), whose tile counting and Discuss counting were adapted so that the new lesson tiles and buttons are not counted as aspect tiles and AI-finding buttons.
